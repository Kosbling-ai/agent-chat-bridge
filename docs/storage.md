# Independent MySQL Store

Node 24 / MySQL 8.4, mysql2 3.24.4. Runtime startup calls `createMysqlStore`, which validates the migration ledger and acquires a dedicated connection writer lock; it never performs DDL. Only one writer may run per database. Writer acquisition has a total deadline covering pool acquisition, database identity and GET_LOCK; late connections are destroyed. Lock connection loss rejects writes and calls `onWriterLost`; the host must stop admission and fail readiness. No business database imports or implicit configuration discovery.

Explicit migration: `node src/storage/migrate-cli.mjs --config /absolute/storage-references.json`. This separate JSON contains only `hostEnv`, `portEnv`, `userEnv`, `passwordEnv`, `databaseEnv`, naming environment variables. Inject credentials through the deployment secret mechanism. Initial DDL is restartable and checksummed, not transactionally atomic. Review migration before applying with a dedicated migration account. Never point test tooling at business databases. Startup does not detect arbitrary manual column drift.

`createPoolFromEnvironment(references, env)` creates a bounded pool. `createMysqlStore({pool,operationTimeoutMs=1800,onWriterLost})` owns that pool until close. SQL deadlines destroy the actual acquired connection; late acquisition is destroyed too. Errors expose stable codes, never driver messages/SQL/credentials. A failed COMMIT is `commit_unknown`: inspect the stable key/read result before repeating any effect. MySQL rollback after disconnection may finish asynchronously. No external calls run inside transactions.

## Contract

All inputs are objects, output fields camelCase; BIGINT sequence/generation may be decimal strings. Read pages are capped at 100. Store performs no chat/network calls.

- `acceptInbound({connectionId,conversationId,eventKey,eventType,messageId?,recalledMessageId?,revision?,occurredAt?,payload,semanticPayload?,policyVersion,passiveContext,source?,conversationType?,agentJob?:{payload},hooks?:[{hookId,payload?}]})` atomically registers inbox, independent agent and hook jobs. Returns eventId, sequence, duplicate, agentJobId, hookJobIds. Same key/different semantic hash rejects `inbound_conflict`; normalized identity must exclude receivedAt/source/isSelf and include true revisions/recalled identity. Existing routing snapshot wins on replay. source is live or history_catchup, and conversationType is p2p/group (inferred from normalized payload when omitted); conflicting explicit and payload values reject. message.received has a canonical first receipt keyed by connection/conversation/messageId, independent of event ID, actor metadata, revision or source. Later live/history receipts preserve the event ledger but create no Agent or hook jobs, even if history content changes; no synthetic message.updated is generated. Returns firstReceipt and duplicateCanonical plus the original first event/job IDs. Real recalled events remain independent and create their own hooks/tombstones.
- `enqueueJob({kind,connectionId,conversationId,idempotencyKey,payload,hookId?})`; kinds agent/hook. Returns id/duplicate. `claimJobs({kind,owner,limit?,leaseMs})` returns jobs plus leaseToken; expired claims can be recovered. A persistent conversation scope row is locked before any inbox/job sequence allocation; concurrent registration cannot commit a later job ahead of an uncommitted earlier job. Hooks preserve per conversation/subscriber registration order and block behind failed attempts until terminal.
- `holdAgentAttempt({id,leaseToken,errorCode})` preserves active session and marks unknown, never claimed automatically. `retryJob` terminal=true atomically releases matching native attempt and marks failed; use only for proven rejection.
- `renewJob({id,leaseToken,leaseMs})`, `retryJob({id,leaseToken,errorCode,nextAttemptAt?,terminal?})`. Lease tokens fence old workers. Retrying a native attempt must first reconcile it; beginAgentAttempt reports recoveryRequired and must never cause a second turn/start.
- `beginAgentAttempt({id,leaseToken,agentId})` locks session and persists intent before RPC, returns generation/nativeThreadId/recoveryRequired. `bindAgentAttempt({id,leaseToken,expectedGeneration,nativeThreadId,nativeTurnId?})` persists admission identifiers. `bufferNativeEvent({connectionId,eventKey,nativeThreadId?,nativeTurnId?,payload})` persists early notifications; `readNativeEvents({connectionId,nativeThreadId,nativeTurnId?,afterSequence?,limit?})` lets the host associate them after admission. An optional nativeTurnId uses its own composite index and excludes null/other-turn events, avoiding repeated whole-thread history scans.
- `finishJobWithOutbox({id,leaseToken,result?,outbox?:[{idempotencyKey,kind,payload}]})` atomically completes native work, releases matching session attempt and records replies. With effects, job stays reply_pending until every outbox entry is sent. Array order is persisted as predecessorId links: only a sent predecessor unlocks its successor, across concurrent workers and restarts. An optional predecessorIdempotencyKey must match the preceding array entry. Any terminal failed delivery atomically changes the job to delivery_failed, preserving completed model work and never re-claiming the agent job. The host reconciles commit_unknown via getJob/getOutbox; stale lease retries do not resend model work.
- `recordOutbox({connectionId,conversationId,idempotencyKey,kind,payload,platformUuid?})`; `claimOutbox({owner,limit?,leaseMs})`; `settleOutbox({id,leaseToken,status,result?,errorCode?,nextAttemptAt?})`. Status sent/unknown/failed/pending; pending only for proven not-sent failures. Expired running is recovered in stable batches of at most 100 and becomes unknown. Only create/reply automatically reclaim unknown within 55 minutes of the persisted first attempt, preserving UUID and payload. The caller must use the official platform UUID guarantee. Unknown upload/reaction/update requires reconciliation. `getJob({id})`/`getOutbox({id})` expose durable status; getOutbox also returns predecessorId, predecessorStatus and blocked. Successors of unknown/failed remain pending with blocked=true; they are never skipped. Independent recordOutbox effects have no dependency.
- `getSession({connectionId,conversationId,agentId})`, `setSession({...key,expectedGeneration,nativeThreadId?,activeRunId?})` (0 creates; active sessions cannot be overwritten), `resetSession({...key,expectedGeneration})` rejects active runs and increments generation. Never bare-delete bindings.
- `appendRunEvent({runId,eventKey,type,payload})`, `readRunEvents({runId,afterSequence?,limit?})` persist/read normalized run history.
- `readPassiveContext({connectionId,conversationId,afterSequence?,limit?})`, `consumePassiveContext({...key,runId,throughSequence})`, `excludeMessage({connectionId,messageId})`. Host determines declaration policy. Recall tombstones support out-of-order delivery; recalledMessageId persists atomically with inbound registration. Revision keys are separate events; edit projection remains caller policy.
- `listKnownConversations({connectionId,conversationType:"p2p",afterConversationId?,limit?})` returns `{items:[{conversationId,conversationType}],nextCursor}` with an indexed stable keyset and limit <=100. Only observed private conversations are listed; conflicting group/private classification rejects. Core must reauthorize catch-up work; this is not a public bot-wide directory API.
- `getCursor({connectionId,key})`, `setCursor({connectionId,key,expectedVersion,value})` implement optimistic consumer cursors. Hook ACK means consumer durable receipt, not business completion.

The Store deliberately has no runtime fake and no public list-of-all-sessions interface. B4 owns authentication, authorization, backpressure, lifecycle logging/error reporting, worker reconciliation and readiness. Current limitations requiring integration review: edit projection and paused recovery need explicit orchestration policies.

## Verification

`npm test` runs offline suites; real MySQL suite is skipped unless explicit BRIDGE_TEST_* environment is supplied. `npm run test:storage` creates disposable MySQL 8.4 on local Unix Docker daemon with random loopback port and in-memory synthetic password, and removes the container. To run a separate core integration suite with the same isolation, use `node scripts/test-storage.mjs test/core.integration.test.mjs`; each invocation starts a fresh schema. Never supply production values. Fault coverage includes real transactions/leases, atomic completion rollback, failed COMMIT response at driver boundary and actual connection destruction deadline. Driver-boundary injection is not a TCP proxy test.
