# Independent MySQL Store

Node 24 / MySQL 8.4, mysql2 3.24.4. Runtime startup calls `createMysqlStore`, which validates the migration ledger and acquires a dedicated connection writer lock; it never performs DDL. Only one writer may run per database. Writer acquisition has a total deadline covering pool acquisition, database identity and GET_LOCK; late connections are destroyed. Lock connection loss rejects writes and calls `onWriterLost`; the host must stop admission and fail readiness. No business database imports or implicit configuration discovery.

Explicit migration: `node src/storage/migrate-cli.mjs --config /absolute/storage-references.json`. This separate JSON contains only `hostEnv`, `portEnv`, `userEnv`, `passwordEnv`, `databaseEnv`, naming environment variables. Inject credentials through the deployment secret mechanism. Initial DDL is restartable and checksummed, not transactionally atomic. Review migration before applying with a dedicated migration account. Never point test tooling at business databases. Startup does not detect arbitrary manual column drift.

`createPoolFromEnvironment(references, env)` creates a bounded pool. `createMysqlStore({pool,operationTimeoutMs=1800,onWriterLost})` owns that pool until close. SQL deadlines destroy the actual acquired connection; late acquisition is destroyed too. Errors expose stable codes, never driver messages/SQL/credentials. A failed COMMIT is `commit_unknown`: inspect the stable key/read result before repeating any effect. MySQL rollback after disconnection may finish asynchronously. No external calls run inside transactions.

## Contract

All inputs are objects, output fields camelCase; BIGINT sequence/generation may be decimal strings. Read pages are capped at 100. Store performs no chat/network calls.

- `acceptInbound({connectionId,conversationId,eventKey,eventType,messageId?,recalledMessageId?,revision?,occurredAt?,payload,semanticPayload?,policyVersion,passiveContext,source?,conversationType?,agentJob?:{payload},hooks?:[{hookId,payload?}]})` atomically registers inbox, independent agent and hook jobs. Returns eventId, sequence, duplicate, agentJobId, hookJobIds. Same key/different semantic hash rejects `inbound_conflict`; normalized identity must exclude receivedAt/source/isSelf and include true revisions/recalled identity. Existing routing snapshot wins on replay. source is live or history_catchup, and conversationType is p2p/group (inferred from normalized payload when omitted); conflicting explicit and payload values reject. message.received has a canonical first receipt keyed by connection/conversation/messageId, independent of event ID, actor metadata, revision or source. Later live/history receipts preserve the event ledger but create no Agent or hook jobs, even if history content changes; no synthetic message.updated is generated. Returns firstReceipt and duplicateCanonical plus the original first event/job IDs. Real recalled events remain independent and create their own hooks/tombstones.
- `enqueueJob({kind,connectionId,conversationId,idempotencyKey,payload,hookId?})`; kinds agent/hook. Returns id/duplicate. `claimJobs({kind,owner,limit?,leaseMs})` returns jobs plus leaseToken; expired claims can be recovered. A persistent conversation scope row is locked before any inbox/job sequence allocation; concurrent registration cannot commit a later job ahead of an uncommitted earlier job. Hooks preserve per conversation/subscriber registration order and block behind failed attempts until terminal.
- `holdAgentAttempt({id,leaseToken,errorCode})` preserves active session and marks unknown, never claimed automatically. `retryJob` terminal=true atomically releases matching native attempt and marks failed; use only for proven rejection.
- `renewJob({id,leaseToken,leaseMs})`, `retryJob({id,leaseToken,errorCode,nextAttemptAt?,terminal?})`. Lease tokens fence old workers. Retrying a native attempt must first reconcile it; beginAgentAttempt reports recoveryRequired and must never cause a second turn/start.
- `beginAgentAttempt({id,leaseToken,agentId})` locks session and persists intent before RPC, returns generation/nativeThreadId/recoveryRequired. `bindAgentAttempt({id,leaseToken,expectedGeneration,nativeThreadId,nativeTurnId?})` persists admission identifiers. `bufferNativeEvent({connectionId,eventKey,nativeThreadId?,nativeTurnId?,payload})` persists early notifications; `readNativeEvents({connectionId,nativeThreadId,nativeTurnId?,afterSequence?,limit?})` lets the host associate them after admission. An optional nativeTurnId uses its own composite index and excludes null/other-turn events, avoiding repeated whole-thread history scans.
- `finishJobWithOutbox({id,leaseToken,result?,outbox?:[{idempotencyKey,kind,payload}]})` atomically completes native work, releases matching session attempt and records replies. With effects, job stays reply_pending until every outbox entry is sent. Array order is persisted as predecessorId links: only a sent predecessor unlocks its successor, across concurrent workers and restarts. An optional predecessorIdempotencyKey must match the preceding array entry. Any terminal failed delivery atomically changes the job to delivery_failed, preserving completed model work and never re-claiming the agent job. The host reconciles commit_unknown via getJob/getOutbox; stale lease retries do not resend model work.
- `recordOutbox({connectionId,conversationId,idempotencyKey,kind,payload,platformUuid?})`; `claimOutbox({owner,limit?,leaseMs})`; `settleOutbox({id,leaseToken,status,result?,errorCode?,nextAttemptAt?})`. Status sent/unknown/failed/pending; pending only for proven not-sent failures. Expired running is recovered in stable batches of at most 100 and becomes unknown. Only create/reply automatically reclaim unknown within 55 minutes of the persisted first attempt, preserving UUID and payload. The caller must use the official platform UUID guarantee. Unknown upload/reaction/update requires reconciliation. `getJob({id})`/`getOutbox({id})` expose durable status; getOutbox also returns predecessorId, predecessorStatus and blocked. Successors of unknown/failed remain pending with blocked=true; they are never skipped. Independent recordOutbox effects have no dependency.
- `getSession({connectionId,conversationId,agentId})`, `setSession({...key,expectedGeneration,nativeThreadId?,activeRunId?})` (0 creates; active sessions cannot be overwritten), `resetSession({...key,expectedGeneration})` rejects active runs and increments generation. Never bare-delete bindings.
- `appendRunEvent({runId,eventKey,type,payload})`, `readRunEvents({runId,afterSequence?,limit?})` persist/read normalized run history.
- `readPassiveContext({connectionId,conversationId,afterSequence?,limit?})`, `consumePassiveContext({...key,runId,throughSequence})`, `excludeMessage({connectionId,messageId})`. Host determines declaration policy. Recall tombstones support out-of-order delivery; recalledMessageId persists atomically with inbound registration. Revision keys are separate events; edit projection remains caller policy.
- `listKnownConversations({connectionId,conversationType:"p2p",afterConversationId?,limit?})` returns `{items:[{conversationId,conversationType}],nextCursor}` with an indexed stable keyset and limit <=100. Only observed private conversations are listed; conflicting group/private classification rejects. Core must reauthorize catch-up work; this is not a public bot-wide directory API.
- `getCursor({connectionId,key})`, `setCursor({connectionId,key,expectedVersion,value})` implement optimistic consumer cursors. Hook ACK means consumer durable receipt, not business completion.

The Store deliberately has no runtime fake and no public list-of-all-sessions interface. B4 owns authentication, authorization, backpressure, lifecycle logging/error reporting, worker reconciliation and readiness. Current limitations requiring integration review: edit projection and paused recovery need explicit orchestration policies.

## Verification

`npm test` runs offline suites; real MySQL suite is skipped unless explicit BRIDGE_TEST_* environment is supplied. `npm run test:storage` creates disposable MySQL 8.4 on local Unix Docker daemon with random loopback port and in-memory synthetic password, and removes the container. To run a separate core integration suite with the same isolation, use `node scripts/test-storage.mjs test/core.integration.test.mjs`; each invocation starts a fresh schema. Never supply production values. Fault coverage includes real transactions/leases, atomic completion rollback, failed COMMIT response at driver boundary and actual connection destruction deadline. Driver-boundary injection is not a TCP proxy test.

## Administrative recovery

`getAgentAttempt({id})` returns only run scope, generation, native IDs, agent, creation time and job status. `enqueueRecovery({runId,callerId,idempotencyKey,expectedGeneration,action,evidence,nativeThreadId?,nativeTurnId?})` registers an administrator action for an **unknown** run whose generation and active session still match. Evidence is required, at most 4096 characters, stored for audit and never returned by `getRecovery({id})`. Caller + key is unique; changed input conflicts. A duplicate remains discoverable after completion.

`claimRecoveries({owner,limit<=100,leaseMs})` returns leased actions, including evidence for the trusted internal worker. Only this worker validates the provider thread/turn, fixed workspace and any terminal-state proof, outside the transaction. `finishRecovery({id,leaseToken,outcome:'applied'|'rejected',errorCode?,verifiedNative?:{threadId,turnId}})` fences the lease and, for applied actions, rechecks the original unknown run, generation and active session. `adopt_turn` requires verified IDs identical to the request and any existing attempt IDs; it binds those IDs and moves the same run to pending, where `beginAgentAttempt` returns `recoveryRequired:true`. It never creates a second model attempt. `abandon_verified` cancels the old run, clears the binding and increments generation without enqueueing another run. Rejection only terminates the administrative action and can close a losing concurrent request after its target changed. Terminal finish with the same lease and result is idempotent, including a lost COMMIT response.

Permanent `bridge_thread_owners` rows bind each connection/native-thread pair to its conversation and agent. Normal bind, explicit session import and administrative adopt claim ownership in the same transaction. Reset/retirement never deletes this record: historic native content cannot be adopted into another conversation. A scope conflict rolls back all attempted binding changes. No provider calls, logs containing evidence, force retry or native thread deletion occur in Store. Core owns authorization and structured management lifecycle/error reporting.

These two tables are in the unpublished initial schema, exercised only in disposable local MySQL. Existing installed schema hashes fail startup until an explicitly reviewed migration is applied; startup does not execute DDL.

## Confirmed artifact cleanup

Internal `artifact_upload` / `artifact_send` effects use the existing ordered outbox. Both require the completed job's trusted `{scope,ref}` payload; a send requires the immediately registered upload predecessor for the same artifact. `getOutbox` adds `predecessorResult`, populated only when that predecessor is confirmed `sent`. Upload uncertainty remains held. Artifact sends use the same original UUID and 55-minute safe retry window as text create/reply; no new retry policy applies to uploads or reactions.

Settling an artifact send to `sent` atomically sets `cleanup_pending`. `listPendingCleanup({afterId?,limit<=100})` returns `{items:[{id,connectionId,conversationId,jobId,payload}],nextCursor}` using the `(cleanup_pending,id)` index and stable keyset order. The single writer's cleanup sweep calls the local, replay-safe file cleanup, then `completeOutboxCleanup({id,connectionId,conversationId})`. This scoped acknowledgement is idempotent and only valid for confirmed sent artifact sends. It clears the marker without changing send/job status. Failure leaves the marker pending; the sweep retries cleanup after restart without resending the message. Because the local operation is safe to repeat, cleanup adds no separate leased job or external queue.

## Idle/rules retirement

Session `lastMessageAt` is the original `bridge_attempts.created_at` of the most recent **confirmed admitted turn**, recorded when `bindAgentAttempt` receives a non-null native turn ID or when management adopts a verified turn. It is the bridge attempt's start time, not the exact provider admission time or event ingest time. Ingest, initial attempt intent, thread-only bind, claims and notifications do not advance it. Repeated recovery cannot refresh it to the current clock. A rejected attempt before turn admission leaves the previous activity time intact; unknown attempts retain the active session and cannot be retired. If no confirmed admission exists, the field is null and core may use the provider's thread creation time for its idle decision.

`rotateIdleSession({connectionId,conversationId,agentId,expectedGeneration,expectedThreadId,expectedLastMessageAt?,reason,idempotencyKey})` performs only a fenced database retirement. Reason is `session_idle`, `rules_updated` or `thread_archived`; core checks idle thresholds, rule timestamps and provider evidence before calling it. The transaction requires matching generation/thread, no active run, and matching previous activity when supplied (including an explicit null). It increments generation, clears the current native binding and persists the old thread/reason/generations/time in `bridge_session_rotations`. Permanent ownership remains. It returns `{generation,retiredThreadId}`; the same scoped key and exact request can be replayed after COMMIT uncertainty, while changed requests conflict. Use a key derived from the waiting run, reason and old generation. Neither this operation nor the audit invokes native archive/delete/create. Subsequent native creation must follow the existing durable attempt-before-RPC protocol.

## Durable guidance to an active turn

`beginSteerAttempt({id,leaseToken,agentId})` only considers agent jobs with no native attempt. It returns `{kind:'inactive'}` when there is no eligible parent, the parent is unknown/has no admitted turn, the same target already rejected this guidance, or another guidance to that parent remains intent/unknown. Otherwise it registers a unique guidance-job/target-run intent and returns `{kind:'new',targetRunId,generation,nativeThreadId,nativeTurnId,clientMessageId}`. `clientMessageId` is the guidance job ID. An existing unresolved intent returns `kind:'recovery_required'`, never permission to repeat the RPC. The parent job serializes all its guidance registration/settlement transactions; no network call holds that lock.

`finishSteerAttempt({id,leaseToken,outcome:'accepted'|'rejected'|'unknown',errorCode?})` fences the guidance lease and stores the outcome audit. Accepted marks only the guidance job succeeded with `{deferred:true,targetRunId,nativeTurnId}`, without a second outbox or any change to parent status. A late provider acknowledgement remains an accepted fact even if the parent completed. Its original intent start time advances session activity only under matching generation/thread, using MAX to avoid moving backwards. Rejected marks the guidance pending for at least one second; that same parent is never steered again, but another admitted parent may receive a new intent with separate audit. Unknown holds the guidance job and prevents further guidance RPCs to that parent until the parent's execution ends; it does not cancel or release the parent. The initial native-attempt operation also refuses unresolved guidance, preventing accidental fallback to a new turn.

`getSteerAttempt({id})` returns the most recent scope/target/IDs/status/time/error facts. Exact terminal finish requests with the same lease remain idempotent after COMMIT response loss. Native management adopt requires an ordinary native attempt and cannot adopt these guidance records. First-stage unknown guidance is observable but has no force retry or automatic new-turn operation. Core supplies the authorized prompt and provider call, distinguishes explicit rejection from uncertainty, and records lifecycle/error reports; Store never repeats a steer RPC or duplicates the parent's final reply.

## Explicit archived rejection before turn admission

`resetRejectedThreadAdmission({id,leaseToken,expectedGeneration,expectedThreadId,reason:'thread_archived'})` is an internal continuation for core's explicit, scoped provider rejection before it sends the turn. It requires the owned running job, the same active session/generation/thread, and a native attempt with no turn ID. In one transaction it audits the retired binding with its run ID, increments session and attempt generation, clears their thread ID, and retains this run's active reservation. The original attempt timestamp and permanent thread ownership remain.

Only the first committed call returns `{generation,nativeThreadId:null,recoveryRequired:false}` to continue native thread creation. The internal job/old-generation/thread/reason key is idempotent, but a duplicate returns current attempt IDs with `recoveryRequired:true`: an old success response is not a new permission to create. A lost database response or process restart thus follows the existing conservative unknown/read path. Once any native turn was admitted, this operation refuses replacement. The provider proof and phase gate remain core's responsibility; there is no public force-reset or provider call inside Store.

`getConversationActivity({connectionId,conversationId,agentId})` returns `{activeRunId,unresolvedGuidance}` through one read-only statement. Any durable native active reservation counts, including unknown/recovery. Guidance counts while its intent/unknown record belongs to a pending/running/unknown guidance job, even after the parent completed. The query uses exact session scope and the steering scope/status index. Core must acquire its local conversation cleanup/execution guard before reading these facts; this query alone is not a lock or permission to race another admission. No database transaction spans file cleanup or provider work.
